PÁGINA 1
 
 
Actividad grupal: “Del comportamiento a la implementación” 
 
Objetivo: aplicar TDD, ATDD y BDD en un caso práctico simple, integrando 
conceptos de DDD. 
 
Equipos: 3 estudiantes 
Cada integrante debe explicar el concepto de las metodologías ágiles (TDD, ATDD 
y BDD) 
 
Caso propuesto: 
Desarrollar una funcionalidad de registro de usuario en un sistema simple. 
 
Fases de la actividad: 
 
ATDD 
Cada grupo define 2 criterios de aceptación junto con un “rol cliente” dentro del 
equipo. 
 
BDD 
Redactan 1 escenario por criterio usando formato Gherkin. 
 
TDD 
Implementan uno de los escenarios: 
Escriben el test unitario que falle 
Codifican lo mínimo para pasarlo 
Refactorizan

Cada grupo define 2 criterios de aceptación desde la perspectiva del usuario. 
Pueden usar la estructura:

Quiero [función] 
Para [beneficio]

Como nuevo usuario, quiero registrarme usando mi correo electrónico, para acceder 
al sistema.

integridad.

PÁGINA 4
 
 
Funcionalidad: Registro de usuario 
 
Escenario: Registro exitoso con datos válidos 
  Dado que ingreso un correo válido y una contraseña de 8 caracteres 
  Cuando confirmo el registro 
  Entonces el sistema crea mi cuenta y muestra un mensaje de éxito 
 
Segundo escenario: 
 
Escenario: Intento de registro con correo duplicado 
  Dado que ya existe un usuario con el correo "test@mail.com" 
  Cuando intento registrarme con el mismo correo 
  Entonces el sistema rechaza el registro y muestra un mensaje de error 
 
FASE 3: TDD – Implementación mínima 
 
Cada grupo toma UNO de los escenarios y lo implementa con TDD. 
 
Paso 1 – Escribir la prueba (RED): 
Ejemplo en pseudoCódigo o JUnit/NUnit/PyTest: 
 
def test_registro_exitoso(): 
    usuario = RegistrarUsuario("test@mail.com", "abc12345") 
    assert usuario.creado == True 
 
 
 

PÁGINA 5
 
 
Paso 2 – Código mínimo (GREEN): 
Implementar solo lo necesario para pasar la prueba. 
 
class RegistrarUsuario: 
    def __init__(self, correo, password): 
        self.creado = True 
 
 
Paso 3 – Refactor: 
Mejorar nombres, estructura, validaciones. 
 
FASE 4: DDD – Modelo del dominio  
 
Cada grupo debe definir: 
 
Entidad principal: Usuario 
Atributos mínimos: correo, nombre (opcional), contraseña 
Reglas de negocio: 
 
No correos duplicados 
Formato válido de email 
Contraseña con mínimo 8 caracteres 
 
Lenguaje común ("lenguaje ubicuo"): 
Usar términos como Usuario, Registro, Validación, Dominio, Repositorio, etc.
